# World ID Web Authenticator

## Overview

A browser authenticator for World ID. Users unlock an encrypted credential vault
with a passkey, review requests from relying-party apps, and approve World ID
proofs. The browser exchanges encrypted requests and responses through the World
ID bridge; the requesting app verifies the returned proof.

The current application connects to World ID staging in the US region and supports
uniqueness proofs using existing Orb and Selfie credentials. Selfie enrollment,
user-presence verification and credential recovery are not yet implemented.

| Component | Technology | Purpose |
| --- | --- | --- |
| Runtime and package manager | Bun 1.4.2 | HTTP server, workspace dependencies and unit tests |
| UI | React 19.2.8, TypeScript 5.9.3 | Request review, passkeys and credential management |
| World ID | `@worldcoin/walletkit-web` 0.27.1 | Account registration, encrypted vault and proof generation |
| Browser build | Vite 8.2.2 | App assets and Web Workers |
| Registry access | viem 2.56.0 | Read the staging RP registry on World Chain |
| Camera guidance | ONNX Runtime Web 1.30.0 with RGBNet | Local face positioning in a Web Worker |
| Browser tests | Playwright 1.62.1 | Chromium and WebKit integration tests |

Versions are pinned in [package.json](package.json) and [bun.lock](bun.lock).
The [Bun server](apps/authenticator/src/server/main.ts) serves the app and its
registry API. [GitHub Actions](.github/workflows/ci.yml) runs tests, lint, type
checks and builds. Automatic Vercel deployment is disabled in
[vercel.json](vercel.json); this repository does not configure a deployment pipeline.

## Quick Start

Install Bun 1.4.2, then run from the repository root:

```sh
bun install --frozen-lockfile
bun run build
bun run start
```

Open **http://localhost:4173**. Use a browser and passkey provider supporting
WebAuthn PRF. Passkeys and camera access require localhost or HTTPS.

For development, `bun run dev` watches the browser build and restarts the Bun
server on changes. It uses the same localhost address.

### Server configuration

| Setting | Default | Configuration |
| --- | --- | --- |
| Listen address | `127.0.0.1` | `AUTHENTICATOR_HOST` |
| Port | `4173` | `PORT`, falling back to `AUTHENTICATOR_PORT` |
| Static assets | `apps/authenticator/dist` | Generated by the browser build |
| Request body limit | 1 KiB | Set in the server entry point |
| Idle timeout | 180 seconds | Set in the server entry point |

For example, `PORT=3100 bun run start` serves the app at **http://localhost:3100**.
Listener settings and HTTP security headers are defined in
[config/authenticator-app-v0.ts](config/authenticator-app-v0.ts).

`bun run build` also produces `apps/authenticator/dist-server/main.js`. To run the
bundled server, use `bun apps/authenticator/dist-server/main.js` from the repository
root, with the browser build present. Set `AUTHENTICATOR_HOST=0.0.0.0` when the
server needs to listen on all interfaces behind an HTTPS ingress.

### HTTP routes

| Method | Route | Purpose |
| --- | --- | --- |
| `GET`, `HEAD` | `/` | Load the authenticator or inspect its response headers |
| `GET`, `HEAD` | Existing asset paths | Serve built JavaScript, CSS, WASM, images and models |
| `GET` | `/api/staging-rp?id=rp_<hex>` | Look up an RP's signer and OPRF key ID in the staging registry |

The registry API returns `{ "signer": "0x…", "oprfKeyId": "0x…" }` for an active
RP. It returns `400` for an invalid ID, `422` for an inactive or uninitialized RP,
and `502` if the registry lookup fails. IDs contain one to sixteen hexadecimal
digits after `rp_`. Unknown API routes return `404`.

Check the server and request validation locally:

```sh
curl -I http://localhost:4173/
curl -i 'http://localhost:4173/api/staging-rp?id=invalid'
```

The first request returns the app headers; the second should return `400`.
Registration, vault operations and proof generation run through WalletKit in the
browser, rather than additional local HTTP endpoints.

### Test an authentication request

Configure the relying-party app to use `http://localhost:4173` as its authenticator
URL. Open the connector link created by that app:

```text
http://localhost:4173/?i=<request-uuid>&k=<url-encoded-base64-key>&b=https%3A%2F%2Fstaging-bridge.worldcoin.org
```

The authenticator loads and validates the request, asks the user to unlock their
wallet, and generates a proof after approval. `b` selects the bridge and defaults
to `https://bridge.worldcoin.org` when omitted. Both official bridge origins are
accepted; the request itself must target staging.

Without a connector link, `/` opens wallet management. **Dev mode** exposes
credential metadata, vault refresh, local credential deletion and runtime details.
Keep the same browser origin when reopening a wallet: its encrypted storage is
local to that origin.

### Camera preview

Install the RGBNet model before building if you want to use camera positioning:

```sh
bun scripts/setup-rgbnet.ts /path/to/RGBNet.onnx
bun run build:authenticator
```

The installer checks the model against the pinned hash. Camera frames are processed
locally for positioning guidance. See [RGBNet setup](docs/rgbnet-browser.md).

## Development and Testing

| Command | What it checks or runs |
| --- | --- |
| `bun run dev` | Browser build watcher and Bun server |
| `bun run lint` | ESLint rules, including browser/server and experiment boundaries |
| `bun run typecheck` | Browser, server, test and script types |
| `bun run test` | Product unit and integration tests |
| `bun run test:authenticator` | Authenticator component, wallet, request and server tests |
| `bun run test:browser` | Build the browser app and run Chromium/WebKit tests on port `4194` |
| `bun run build` | Build browser assets and the Bun server bundle |

Install the browser test runtimes once with
`bun x playwright install chromium webkit`. Playwright covers request review,
proof delivery, passkey/vault behavior, camera workers and accessibility using
controlled upstream responses. Its configuration is in
[tests/e2e/playwright.config.ts](tests/e2e/playwright.config.ts).

## Repository Structure

| Path | Contents |
| --- | --- |
| `apps/authenticator/src` | React app, wallet integration, request handling and Bun server |
| `apps/authenticator/test` | Authenticator regression tests |
| `packages` | Shared contracts and browser-admission policy |
| `config` | Server listener settings and HTTP security headers |
| `scripts` | Model installation and other developer utilities |
| `tests` | Integration fixtures, browser tests and Playwright configuration |
| `experiments` | Standalone demos excluded from the main app build |
| `docs` | Design notes and integration references |

Project configuration stays at the root: `vite.config.ts` defines the browser
build, `eslint.config.mjs` defines lint rules, and `tsconfig.json` provides shared
compiler settings. The client, server, test and tools TypeScript configurations
select the files and runtime types for each environment.
